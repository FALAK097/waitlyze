## Templates and tests

Open the waitlist's Email tools → Templates. Edit the signup or offboarding template, including subject, preview text, heading, message, and additional content. Markdown and `{{waitlist}}` are supported.

<Callout title="Tests use the saved template">
Save your edits before sending a test to a valid email address. A test is a real email, not an on-screen preview.
</Callout>

## Broadcasts

<Steps>
<Step>
### Create and save a draft
Write the subject and message, then save. Changing the content invalidates the recipient preview.
</Step>
<Step>
### Preview eligible recipients
The audience includes verified subscribers who opted in. Unsubscribed and suppressed addresses are excluded.
</Step>
<Step>
### Review and confirm
Review the current count before confirming the send. You can cancel remaining messages, but messages already handed to the provider may still arrive.
</Step>
</Steps>

## Automations

| Recipe | When it runs |
| --- | --- |
| Welcome after confirmation | After a subscriber verifies their email. |
| Referral reminder | After confirmation, when the subscriber still has no verified referrals at send time. |
| Referral milestone | When an eligible verified referral reaches the configured milestone. |

Set a delay from zero to 168 hours. Milestones accept one to 100 verified referrals. The milestone message supports the `{{referral_count}}` variable with the subscriber's current count. Save changes before enabling a recipe. Changes create a new version; already scheduled runs keep their saved version.

Pausing cancels scheduled messages. A message already being handed to the provider may still arrive.

## Delivery and consent

<Callout type="warn" title="Verification does not mean marketing consent">
Broadcasts and automations require both verified email and explicit marketing opt-in. Unsubscribe and workspace suppressions are checked again before delivery.
</Callout>

Email delivery requires a configured sender and dispatcher. A saved recipe or configured secret alone does not prove that the dispatch scheduler is running. Use [Resend](/docs/resend) for your own verified sender.
