Use the Waitlyze API from your server or AI agent to create signups, inspect status, and operate every waitlist workflow without opening the dashboard.

## Supported public signup endpoints

| Method | Endpoint | Purpose | Guide |
| --- | --- | --- | --- |
| <span className="docs-http-method docs-http-method--post">POST</span> | `/api/waitlist` | Create or replay a signup and return live position, points, and `total_signups`. | [Create signup](/docs/api/create-signup) |
| <span className="docs-http-method docs-http-method--get">GET</span> | `/api/waitlist?email=…` | Look up a subscriber's live position, points, and `total_signups`. | [Look up signup](/docs/api/lookup-signup) |
| <span className="docs-http-method docs-http-method--post">POST</span> | `/api/waitlist/points` | Credit a configured off-site action or custom event. | [Award custom points](/docs/api/award-points) |

## Full platform API v1

Every dashboard workflow has a matching scoped endpoint under `/api/v1` documented in the OpenAPI schema at `/openapi.json`:

- **Workspaces and team**: `/api/v1/workspaces`, `/members`, `/audit`, `/suppressions`, and Resend or Cloudflare email integrations
- **API keys**: `/api/v1/api-keys` with workspace-scoped or waitlist-scoped permissions
- **Waitlists and page builder**: `/api/v1/waitlists`, `/api/v1/waitlists/{id}`, `/page` for sections and rules, `/rehearsal`, `/publish`, `/pause`, and `/rollback`
- **Subscribers and referrals**: `/api/v1/waitlists/{id}/subscribers`, `/subscribers/{subscriberId}`, `/subscribers/{subscriberId}/points`, `/subscribers/batch`, `/subscribers/export`, and `/referrals/reviews`
- **Analytics and alerts**: `/api/v1/waitlists/{id}/analytics`, `/domain`, `/email-sender`, `/notifications/{slack|discord}`, and `/webhooks`
- **Emails and automations**: `/broadcasts`, `/broadcasts/preview`, `/broadcasts/{broadcastId}/send`, `/email-templates`, `/automations`, and `/email-logs`

## Authentication and scope

Create a key in **Settings → API keys** or via `POST /api/v1/api-keys` and pass it in an `X-Api-Key` or `Authorization` header with `Bearer wl2_…`. OAuth 2.0 bearer tokens work across `/api/v1` and `/mcp`. See [API keys](/docs/api-keys) for scope options, workspace keys, rotation, and rate limits.

## Choose a connection pattern

- Use the [hosted page or embed](/docs/embed) when you want Waitlyze to own the browser form without a backend integration.
- Use [Create signup](/docs/api/create-signup) when your server needs to control the signup flow or return position and referral data to a custom frontend.
- Use Platform API v1 at `/api/v1` or the [MCP server](/docs/mcp) to automate waitlists, analytics, broadcasts, subscribers, and domains from CI or AI agents.
- Use [webhooks](/docs/webhooks) when your stack reacts asynchronously to live signups, verification, referrals, or reward unlocks.
