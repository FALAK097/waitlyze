---
title: Award custom points
description: POST /api/waitlist/points — credit points for a configured off-site action.
---

Award points when a verified subscriber completes an action Waitlyze cannot observe directly, such as finishing a survey or joining a Discord community.

## Request

Call `POST /api/waitlist/points` with an API key in the `X-Api-Key` or `Authorization: Bearer` header. This endpoint does not accept a key in the JSON body. Configure the event key and default points under **Rewards** in the waitlist builder only when you want the waitlist's defaults; a request that supplies explicit `points` does not need a configured event.

```bash title="Award points for a completed survey"
curl --request POST "$WAITLYZE_URL/api/waitlist/points" \
  --header "Content-Type: application/json" \
  --header "X-Api-Key: $WAITLYZE_API_KEY" \
  --data '{
    "waitlistId": "YOUR_WAITLIST_ID",
    "email": "person@example.com",
    "event": "survey",
    "idempotencyKey": "survey-response-123"
  }'
```

Pass either `signupId` or `email`. `event` is required, but it only needs to match a configured key when you omit `points`: an explicit `points` value can override a configured default or credit an event that is not configured at all. Reuse `idempotencyKey` for retries so an action is not credited twice.

## Eligibility and errors

Only verified signups earn points. Unverified signups return `409`; unknown event keys return `400` unless you supply explicit points. See the [full API guide](/docs/api#award-custom-points) for the response shape, fraud checks, and rate limits.
