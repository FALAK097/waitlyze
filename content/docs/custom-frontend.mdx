title: Custom frontend guide
description: Ship your own signup UI on the Signup API, embeds, referrals, domains, and email.
---

This guide wires the whole public surface together: a form you own, Waitlyze-owned verification and storage, referral sharing, your domain, and your sender. Follow it in order — each step assumes the previous one works.

## 1. Collect signups with the API

Build any form (React, plain HTML, mobile app backend) and POST from **your server** with a [Signup API](/docs/api) key. Never ship the key to the browser — proxy through your backend.

```js title="Your backend → Waitlyze"
const response = await fetch("https://waitlyze.falakgala.dev/api/waitlist", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Idempotency-Key": orderId, // reuse on retry; see Signup API
  },
  body: JSON.stringify({
    apiKey: process.env.WAITLYZE_API_KEY,
    waitlistId: "YOUR_WAITLIST_ID",
    email,
    referral_code: refCode, // optional; snake_case or referralCode
  }),
});
const { data } = await response.json();
// data.position, data.referral_code, data.referral_link → render confirmation UI
```

Show `data.position` (“You're #9 in line”) and, when present, `data.referral_link` with a copy button. On `409`, read `data.position` — the email already joined, so show its place instead of an error wall. Poll `GET /api/waitlist?waitlistId=…&email=…` for a “check my spot” box.

## 2. When to use the embed instead

If you do **not** need custom logic, skip the API: paste the [embed snippet](/docs/embed) (`data-key-id` is a public waitlist ID, no secret). The embed forwards `?r=CODE` and UTM parameters automatically, sizes itself, and needs no backend. Many teams combine both — embed for the marketing site, API for in-product or mobile flows — because both feed the same waitlist, position engine, and referral graph.

## 3. Turn on referrals

In Waitlist settings → **Referral sharing**, enable sharing ([Referrals](/docs/referrals)). From then on:

- API responses include `referral_code` + `referral_link` for every signup.
- Pass a friend's code as `referral_code` (API), `?r=CODE` (hosted page), or inherit it from your page URL (embed).
- Credit counts only after **both** sides verify — gate rewards on the [`referral.completed` webhook](/docs/webhooks), never on signup alone.
- Review flagged referrals in Subscribers → Referral review.

## 4. Serve it from your domain

Add `join.example.com` in Waitlist settings → **Custom domain** ([Custom domains](/docs/domains)). It serves the same published revision as the hosted `/w/slug` page, so your API-built confirmation screens can link to a first-party URL. `referral_link` values in API responses still point at the Waitlyze hosted URL — rewrite the origin to your domain when rendering if you prefer (`/w/slug?r=CODE` path shape is identical).

## 5. Send from your domain

Connect [Resend](/docs/resend) (Settings → Integrations → Resend) so verification, broadcast, and automation mail arrives from your address instead of the deployment default. Until a test send succeeds the deployment sender is used — launch the custom frontend only after connection status reads **Active**, or your verification emails may land in spam and stall the double opt-in your positions depend on.

Today one workspace shares one sender. Per-waitlist sender identity (each waitlist with its own verified domain) is planned — the API contract will be a per-waitlist `fromEmail` override with workspace fallback; there is no per-waitlist sender to configure yet.

## Launch checklist

- [ ] Waitlist is **Published** (drafts reject every channel).
- [ ] Test signup via API returns `200` with `position` + `referral_link`.
- [ ] Duplicate email returns `409` with the existing `position`.
- [ ] Status lookup returns the same position for the test email.
- [ ] `referral.completed` webhook arrives on a verified referral (test with two real addresses).
- [ ] Resend status is **Active**; verification email arrives from your domain.
- [ ] Custom domain reads **Ready** (or ship on the hosted URL first).
