Waitlyze sends a short Slack message when a published waitlist reaches **1, 10, 100, or 1,000 signups**. This is a best-effort milestone notification, not a complete event feed.

## Connect Slack

1. In Slack, add an incoming webhook for the channel that should receive milestones and copy its URL. Slack webhooks must use the official `hooks.slack.com` host.
2. Save it for the waitlist with `PUT /api/wait-lists/{id}/notifications/slack` and JSON body `{ "webhookUrl": "https://hooks.slack.com/services/…" }`.
3. Send a test with `POST /api/wait-lists/{id}/notifications/slack`. The channel connects only if Slack accepts the test message.

Use `GET` on the same path to check status or `DELETE` to disconnect.

## Access and delivery

The channel endpoint requires a signed-in Waitlyze session with waitlist-management access. It does not accept a signup API key. There is not yet a dedicated Slack settings form in the app.

The webhook URL is encrypted and never returned by the endpoint. Each waitlist can connect one Slack channel. Messages contain only the waitlist name and milestone count; failures mark the channel as needing attention without blocking signups, owner email, or customer webhooks.

For signed events, retries, and delivery history, use [Webhooks](/docs/webhooks). See [Notifications](/docs/notifications) for shared behavior and [Integrations](/docs/integrations/overview) for other connections.
