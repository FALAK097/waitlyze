Referrals turn subscribers into inviters. Enable sharing, let verified subscribers share links, then review credit in Subscribers.

## Enable sharing

In Waitlist settings → **Referral sharing**, turn on Enable referral sharing. Any editor with campaign access can toggle it. When on:

- Confirmation states show a personal referral link.
- Hosted, embed, and API signups can carry a code.
- Subscribers tab gains a **Referral review** view.

Turning it off hides new sharing UI but preserves existing referral records.

## How a code travels

<Callout title="Codes are waitlist-scoped">
A code belongs to one waitlist. Passing another waitlist's code via API is rejected.
</Callout>

| Channel | How the code travels |
| --- | --- |
| Hosted page | `?r=CODE` query parameter on the shared link. |
| Embed | Forwarded from your page URL, like the hosted page. |
| Signup API | `referralCode` (or `referral_code`) field in the JSON body. Responses return the new signup's own `referral_code` + `referral_link`. See [Signup API](/docs/api). |

## Verified credit rules

Credit counts only when **both** the inviter and the invited email are verified, the referral is eligible, and review status is `CLEAR` or `APPROVED`.

These do **not** count automatically:

- Self-referrals (same address inviting itself).
- Duplicate signups for an already-registered email.
- Referrals flagged `NEEDS_REVIEW` until an owner/admin approves them.
- Unverified inviters or invitees.

Open Subscribers → Referral review to approve or resolve flagged referrals. The list shows inviter, invitee, reason, and resolution for the latest 50 non-clear items.

## Queue position

Position uses eligible campaign referrals plus signup ordering. It answers “where am I right now?” — not “what reward do I get?” Referrals do not automatically deliver rewards or unlock product access. Build your own reward rules on top of verified counts and [webhook events](/docs/webhooks) — specifically `referral.completed`, which fires when the inviter earns verified credit.
