Connect the part of your launch workflow that needs to leave Waitlyze. Some connections are configured in workspace or waitlist settings; others are event-based recipes rather than native apps. Each guide calls out the setup path and its current limits.

## Email delivery

Use Resend to send waitlist email from a verified domain. The workspace connection is managed in **Settings → Integrations**; a waitlist can also have its own sender credentials on supported sending paths.

## Event delivery

Use Waitlyze webhooks when another system needs a signed, retryable event for signup, verification, referral, or milestone activity. The payload contains IDs rather than subscriber email addresses.

## Automation recipes

Zapier is not a native Waitlyze app. Connect it through **Webhooks by Zapier** with the Catch Raw Hook trigger, then use a Code step and the Waitlyze signing secret to verify each event's raw body and `x-waitlyze-signature` header before the Zap acts on it. Email-provider sync follows the same webhook-first pattern.

## API or webhook?

Use the [API](/docs/api/reference) when your server needs to create a signup, retrieve its status, or award points. Use a [webhook](/docs/webhooks) when Waitlyze should tell your system that something happened. Slack and Discord are simple milestone notifications; Zapier is a recipe that consumes the same webhooks.
