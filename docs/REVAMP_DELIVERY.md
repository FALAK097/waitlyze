# Transactional email delivery

The public signup route records a verification message in `outbox_events` in the same database transaction as the signup and verification token. A scheduler must call `POST /api/internal/email-outbox` regularly with `Authorization: Bearer <OUTBOX_DISPATCH_SECRET>`. The worker claims events atomically, retries transient Resend failures with a bounded delay, sends the event key as the provider idempotency key, and removes the raw token from the event after terminal processing.

Configure `OUTBOX_DISPATCH_SECRET` in the deployment environment and call the endpoint about once per minute from the host's scheduler. The route returns counts only; it does not include recipient addresses, message content, tokens, or provider errors. Keep the response private. The Emails page shows the five latest verification sends and flags when the dispatch key is missing or recent sends failed. A configured key alone does not prove that a scheduler is running.

Create a Resend webhook for `email.bounced` and `email.complained`, pointed at `/api/webhooks/resend`, and set its signing secret as `RESEND_WEBHOOK_SECRET`. The route verifies the original raw request body with Resend's SDK, deduplicates provider event IDs, and suppresses the matching address for that workspace after permanent bounces or complaints; temporary bounces stay retryable. Provider event rows do not retain recipient addresses. Events arriving before the send worker records the provider message ID are reconciled when the worker completes.

An outbox status of `DELIVERED` means Resend accepted the message and returned an ID. It does not mean the recipient's mailbox accepted or displayed it; bounce and complaint callbacks provide that later signal. Resend idempotency keys are retained for 24 hours, while retries stop after six attempts within roughly 30 minutes, so automatic retries stay inside the provider's deduplication window. See [Resend idempotency keys](https://resend.com/changelog/idempotency-keys) and [Resend webhook verification](https://resend.com/changelog/managing-webhooks-via-api).
